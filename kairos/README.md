# Kairos Markets: Simulated Multi-Asset Trading Platform (Client Demo)

Kairos is an interactive demonstration of a unified trading and investment platform covering **stocks, options (CE/PE), crypto, forex and a consolidated portfolio**, plus an RBAC-protected **back office**.

> **Everything is simulated.** Prices come from a deterministic model, not a market feed. There is no connection to any exchange, broker, bank, payment rail, crypto custody or forex execution venue. The app makes no claim of regulatory approval or partnership. Binary options are not offered anywhere.

The login page has a one-click **Continue with the demo account** button. Admin credentials are never shipped to the browser.

The demo user starts with an initial **₹10,00,000** deposit and a seeded history: stock holdings (RELIANCE, TCS, HDFCBANK, INFY, ICICIBANK, ITC), crypto (BTC, ETH, SOL, XRP), forex positions (long USD/INR, short EUR/USD, long GBP/USD), live NIFTY options (long call, short put), a closed BANKNIFTY trade, a withdrawal and deposit, two resting limit orders, a watchlist and approved simulated KYC. All of this is generated by **running back-dated orders through the real engine**, so every figure reconciles with the ledger. Eight further personas fill the admin views. Any user can reset their account from **Profile → Reset demo account**.

## Quick start (local)

Prerequisites: Python ≥ 3.11, Node ≥ 20, PostgreSQL ≥ 14, and optionally Redis.

```bash
createuser -P kairos   # password: kairos  (or set KAIROS_DATABASE_URL)
createdb -O kairos kairos
```

```bash
cd backend
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/alembic upgrade head          # migrations
.venv/bin/python -m app.seed            # instruments, demo accounts (idempotent; --reset to rebuild demo user)
.venv/bin/uvicorn app.main:app --port 8000
```

```bash
cd frontend
npm ci
npm run build && npm start              # or: npm run dev
```

Open http://localhost:3000. The Next.js server proxies `/api/*` to `KAIROS_API_ORIGIN` (default `http://127.0.0.1:8000`), so the browser only ever talks to one origin.

Or run everything with Docker: `cp .env.example .env && docker compose up -d --build` (see [Deployment](docs/DEPLOYMENT.md)).

## Demo walkthrough (≈10 minutes)

1. **Login**: `/login` → *Continue with the demo account*.
2. **Dashboard**: account value, today's and overall P&L, available cash, index strip, performance curve, allocation, watchlist, open positions, recent orders, market movers.
3. **Stock market**: `/stocks`: search, sort by movers or activity, sparklines.
4. **Select a stock**: e.g. RELIANCE: candlestick/line chart (1D–5Y), key stats, your position.
5. **Place an order**: ticket with Market/Limit → live server-side preview (price, value, fees, available-after) → **Review** → **Confirm** → execution result, toast, updated balance.
6. **Options chain**: `/options`: NIFTY / BANKNIFTY / RELIANCE, weekly and monthly expiries, OI bars and change, volume, IV, optional Greeks, ITM shading, spot marker, PCR.
7. **Buy an option**: hover a premium → **B**. The ticket shows the full-premium-at-risk warning and the payoff diagram.
8. **Sell an option**: hover → **S**. Shows SPAN-style margin to block and the *unlimited loss* (calls) or *large loss* (puts) disclosure, which must be acknowledged before confirming.
9. **Crypto**: `/crypto`: featured cards and the full list.
10. **Buy Bitcoin**: `/crypto/BTC`: fractional quantity (min 0.0001).
11. **Forex**: `/forex`: jurisdiction note, pairs list.
12. **Open a currency position**: e.g. EUR/USD *Sell / Short* 1 lot: margin and leverage warning.
13. **Portfolio**: totals, P&L reconstructed over time, allocation, largest holdings, sector exposure. **Positions**: live M2M, margin utilisation, close buttons.
14. **Orders and transactions**: order book with cancel for open limit orders; full cash ledger with CSV export. **Wallet**: add or withdraw demo funds.
15. **Admin**: sign in as admin → `/admin`: KPIs, activity charts, users (enable/disable, inspect, reset), KYC approve/reject, instruments (enable/disable, reprice, volatility), all orders and transactions, fee schedule and trading controls (halt, KYC requirement, INR-pairs-only forex, option-writing switch, leverage), reports and audit log.

Automated version: `node frontend/e2e/demo-walkthrough.cjs` (needs both servers running; see [Test report](docs/TEST_REPORT.md)).

## Remaining limitations

- **Not deployed yet**: no suitable existing hosting target was available (see [Deployment](docs/DEPLOYMENT.md) for exact steps).
- **Simulated data only**: prices come from a seeded fractal-noise model in a simulated 24×7 session. There are no market hours, holidays or circuit limits. Stock "fundamentals" are illustrative.
- **Execution model**: fills at the simulated last price (no order-book depth, partial fills, slippage or bid/ask crossing). Limit orders fill when the matcher observes the price at or through the limit (every 3 s, and on page requests).
- **Margin model**: simplified SPAN-style formula for short options, notional/leverage for forex. There are no automated margin calls or liquidations; risk is shown as utilisation and warnings.
- **Admin price overrides** apply a multiplier from the moment they are set. A new override replaces the previous one, which can shift the chart history between the two override times.
- **Options**: European-style, cash-settled at intrinsic value on expiry. The underlyings are NIFTY, BANKNIFTY and RELIANCE.
- **No outbound email**: password-reset links are shown in the UI only when `KAIROS_EXPOSE_RESET_LINKS=true`. The shared demo/admin accounts cannot be reset or have their passwords changed.
- **WebSocket stream** (`/api/market/ws`, live updates every 2 s) works directly and through the Next.js Node server proxy (verified). On serverless hosts without WebSocket support the UI falls back to 2–8 s polling.
- **Native mobile apps** are not included. The REST API and Bearer-token auth are ready for them.
- **Not production compliance**: KYC is a simulated workflow, and there is no real identity verification, AML, suitability or reporting.
