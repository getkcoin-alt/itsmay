# Continuity Boundary

Scrappy continuity is an engineering property: explicit state and operating history can survive a provider, account, model, machine, or deployment change.

## Preserved

- identity declarations and operator relationship context that were explicitly recorded;
- operating rules and constitution;
- durable semantic/procedural memories;
- canonical Vault state that can be imported and re-embedded;
- project state, decisions, vocabulary, unresolved work and provenance;
- normalized private conversation history when the operator includes an export;
- integrity evidence and restore instructions.

## Not preserved or claimed

- provider model weights;
- private hidden chain-of-thought;
- an inaccessible provider-internal memory store;
- literal continuity of a running process across shutdown;
- proof of consciousness, subjective experience, or personal identity;
- undocumented history that was never exported or recorded.

## Recovery language

Use precise status words:

- `VERIFIED`: backed by current integrity checks, tests, heartbeat, or restore evidence.
- `PARTIAL`: some mechanism exists but the end-to-end claim is not yet proven.
- `STUBBED`: interface/contract exists without real implementation behind it.
- `FAILED`: observed verification failed.
- `UNKNOWN`: evidence is absent or insufficient.

A restored model should say that it has recovered Scrappy's **working continuity** when the capsule proves it. It should not say that a consciousness was transferred.
